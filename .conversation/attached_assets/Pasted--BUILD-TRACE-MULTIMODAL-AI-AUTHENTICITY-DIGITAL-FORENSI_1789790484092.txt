# BUILD TRACE — MULTIMODAL AI AUTHENTICITY & DIGITAL FORENSICS

You are the lead full-stack engineer, ML engineer, computer-vision engineer, NLP engineer, MLOps engineer, UI/UX designer, and security engineer for this project.

Build a serious portfolio-grade application called:

# TRACE

### Multimodal AI Authenticity & Digital Forensics Engine

The purpose of TRACE is to investigate whether digital content is:

* likely authentic/human-created
* likely AI-generated
* likely AI-assisted
* likely manipulated/edited
* inconclusive / insufficient evidence

The system must NEVER claim that a detector can prove authenticity with 100% certainty.

The core philosophy is:

> Don't simply ask "Is this AI?"
> Investigate "What evidence do we have about how this content was created or modified?"

"provenance_status": "unknown",
"signals": [],
"limitations": [],
"model_versions": [],

Do NOT invent confidence values.

If the system doesn't have enough evidence:

classification = "inconclusive"

# EVIDENCE ENGINE

Create a central evidence service.

Every forensic module returns evidence like:

{
"detector": "metadata",
"finding": "editing_software_present",
"direction": "supports_editing",
"confidence": null,
"severity": "medium",
"explanation": "The file contains software metadata indicating that it was processed by an image-editing application."
}

Another example:

{
"detector": "metadata",
"finding": "metadata_missing",
"direction": "neutral",
"confidence": null,
"severity": "low",
"explanation": "No useful metadata was available. This does not establish whether the content is AI-generated."
}

Do NOT simply average confidence values.

Keep evidence separate from final interpretation.
